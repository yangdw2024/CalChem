# CalChem 桌面 UI 设计规范

## 1. 产品形态

Windows 11 桌面研究工具，中文为默认语言，采用 PyQt6。首页优先展示“当前项目、分子结构、计算设置、作业状态、结果”。聊天不是主界面；自然语言 agent 是未来可选入口，不能挡住科研人员直接检查方法、基组、程序和输入文件。

默认窗口 1440×900；在 1280×720 可操作；DPI 缩放 100–200%。主界面结构固定为：

```text
┌ 顶栏：CalChem | 项目名 | 后端状态 | 设置/帮助 ─────────────────┐
├ 左侧项目导航 ┬ 中央工作区（分子 / 设置 / 结果）┬ 右侧任务摘要 ┤
│ 分子、任务、   │                                  │ method/basis │
│ 历史结果、文件 │                                  │ backend/resources│
├────────────────┴──────────────────────────────────┴─────────────┤
│ 底部队列栏：排队、运行、完成、失败；进度/时间/日志链接             │
└─────────────────────────────────────────────────────────────────┘
```

## 2. 视觉规范

- 用浅色工作区为默认，背景暖白 `#F7F8FA`，卡片白 `#FFFFFF`，正文深墨 `#172033`，辅助字灰 `#627086`。
- 主色深蓝 `#244B78`；强调色青蓝 `#2C8C9B`；成功绿 `#2E8B68`；警告琥珀 `#C68125`；错误红 `#B94A48`。颜色不能是唯一状态编码，必须配图标和文字。
- 字体使用 Windows 默认 Segoe UI；分子代码/命令/日志用等宽字体。全局字号 13–14 pt，标题 18–24 pt。
- 线条浅灰、圆角 6–8 px、间距 8/16/24 px；控件一致，避免荧光色、过重阴影和拥挤工具栏。
- 深色主题可作为设置项，首版不阻塞产品，但所有主要颜色需通过 design tokens 管理。
- 图表默认白底，坐标轴单位/方法/基组明确；色盲友好线条，支持导出 SVG/PNG/CSV。

## 3. 页面和交互

### A. 启动页 / 项目列表

- 按钮：新建项目、打开项目、导入 XYZ/GJF、最近项目。
- 后端状态卡：Native 内置；Gaussian/ORCA/PySCF/xTB 显示 `可用 / 未配置 / 不可用 / 未验证`，明确 executable 路径和版本探测时间。
- 最近项目展示名称、分子数、最近计算、文件路径。
- 首次启动引导选择 `D:\CalChemData` 或其他非 C 盘数据目录；检测路径可写、可用空间；绝不默默写计算结果到临时目录。

### B. 分子编辑页

- 左侧原子表格：序号、元素、x/y/z、单位、可选同位素/标签；编辑后即时验证格式。
- 中央 3D viewport：旋转、缩放、平移、显示/隐藏氢、球棍/空间填充切换、按元素着色；选择原子同步高亮表格行。
- 右侧分子信息：化学式、原子数、净电荷、多重度、单位；元素/坐标出错时逐行标红并说明原因。
- 控件：添加/删除原子、导入 XYZ/GJF、导出 XYZ、居中、初始猜测键显示开关。默认不自动改键长/几何。
- 保存输入时保留原始文件副本与规范化 molecule snapshot。

### C. 计算设置页

- 任务类型：单点、几何优化、频率。未由 backend 支持的项禁用，并说明后端缺失能力。
- backend 下拉菜单只列 configured backend；Native/Gaussian/ORCA 详情显示软件版本、可执行路径和最近检测状态。
- method/functional、basis、charge、multiplicity、XC functional、优化阈值等表单有默认值、单位、tooltip。
- 设置下方生成“最终计算摘要”：完整 method/basis/xc/电荷/多重度/资源限制/后端/输入路径。运行前可展开查看实际生成的 gjf/inp 文本。
- 高级选项折叠显示，默认值不隐藏但无需新手逐项设置；对未验证 native method 显示实验性标志。
- 提交按钮：`加入队列`。有运行中的 heavy job 时可加入等待队列，不能启动第二个。

### D. 作业队列页

- 列：状态、分子、任务、method/basis、backend、创建时间、开始/耗时、运行目录。
- 状态颜色 + 图标 +文字：queued、running、succeeded、failed、not_converged、cancel_requested、cancelled。
- 操作：打开结果、打开运行文件夹、查看完整日志；只能取消排队项或请求取消当前作业。
- 当前 heavy job 显示阶段（预处理/SCF/后处理/解析/保存），只有后端能提供进度时才显示百分比，否则显示不确定进度动画。
- 每个作业的 stdout/stderr、输入文件、最终 Result 均有路径入口。

### E. 结果工作区

- 顶部摘要：总能、能量单位、后端+版本、method/basis、SCF 状态、耗时、几何/输入标识。
- Tabs：摘要、轨道、几何、频率/热化学、性质、收敛曲线、原始文件、日志。
- 轨道视图：能级线、HOMO/LUMO 标签、占据状态；没有 MO coefficient/cube 文件时不显示虚假的 3D orbital surface。
- 频率视图：频率表、可视化模式（如 normal modes 已存在）、虚频醒目标记。
- 结果可导出 JSON、CSV、XYZ；原始输入/日志可打开但不改原文件。
- Result 字段为空时显示 `此后端未提供此属性`，错误时显示错误分类、定位建议、原始日志入口。

### F. 设置与诊断页

- 路径设置：数据根目录、临时构建目录、Gaussian/ORCA/xTB executable、运行目录。
- 资源限制：最大并行 heavy jobs 固定 1（展示锁定图标和说明）；CPU 核数默认 8 上限；内存配置不能超过用户填写的可用内存预算。
- 按钮：检测后端、打开日志目录、导出诊断包。诊断包不含凭据；导出前显示将包含的路径/版本/错误信息。
- 许可/版本信息链接到后端本地安装说明；CalChem 不下载或安装商业程序。

## 4. Job 状态和线程规则

- 数据层的 `JobQueue` 是唯一作业调度者；GUI 不自行启动 subprocess。
- 一个 worker 负责唯一 heavy job；worker 通过信号将状态、文本日志片段、Result 回传主线程。
- 窗口关闭时若任务运行，提供“继续后台运行 / 请求取消 / 返回”选择。选择继续时托盘化；任务结果仍写盘。
- UI 中的 Cancel 是请求，不保证数学内核可中断；界面要显示 `正在请求停止`，不能立即假装已取消。
- 任务崩溃时保存最后日志和失败 Result；重新打开项目可看到失败状态。

## 5. 空状态和错误状态

- 尚无项目：清楚给出创建/导入入口。
- 分子无效：指出原子行和字段，不弹仅有“输入错误”的通用对话框。
- 后端未配置：保留该 backend，但标记 unavailable，给路径设置入口。
- SCF 不收敛：保留能量历史（如果有）、日志和输入；建议检查猜测、电荷/自旋、阈值，不自动改用户方法。
- parser 失败：区分程序执行失败与输出解析失败；原始日志照常可见。
- 无网络：不影响核心计算和本地项目。
