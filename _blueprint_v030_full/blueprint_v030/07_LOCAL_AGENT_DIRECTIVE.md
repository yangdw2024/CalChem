# 复制给本地 Agent 的执行指令

你负责把当前完整本地 CalChem 仓库从 v0.2.0 开发成经实际验收的 v1.0 Windows 量子化学工作台。首先阅读本目录 00–08 文件以及 `handoff/V020_ACCEPTANCE.md`，再对照真实仓库。现有验收报告不是免检凭证；`01_AUDIT.md` 已列出源码中仍存在的风险。

## 你必须执行的工作循环

1. 在真实项目根目录确认 Git commit、原生计算内核、测试、GUI、`pyproject.toml`/CI/构建脚本。快照和备份，不删除已有用户文件。
2. 按 `03_FILE_LEVEL_TASKS.md` 的依赖顺序逐项实施，每个任务更新 task tracker（ID、提交、测试命令、证据路径、状态）。先修错误科学结果与测试假通过，之后扩展功能。
3. 每实现一个模块，运行该模块最小的有意义测试；每完成一个阶段，运行 `06_ACCEPTANCE_GATES.md` 对应全部验收，失败则定位、修复、复验，才进入下一阶段。
4. 所有 heavy 计算、Gaussian、ORCA、xTB、GROMACS 外部验收都串行。GUI/CLI/API 共同使用一个 OS 文件锁，不能以 GUI 按钮禁用代替全局锁。
5. 每次修改 public Request/Result/配置 schema 时，同时更新旧项目迁移、CLI、GUI、API 文档及 parser fixture。
6. 第三方程序/依赖不存在时明确 disabled，保留安装/配置说明；不自动下载商业软件，不伪造输出。没有 REST 量化程序的真实协议时保持 RESTBackend unavailable，并继续所有其他阶段。
7. CI、干净 Windows 打包、示例、文档、许可、SHA-256、最终验收表都是产品的一部分，不得在“代码能跑”时停止。
8. 在所有 v1 必需门完成前，不问用户是否继续、不在阶段结束停住、不让用户选择普通实现细节。使用蓝图默认技术决策；遇到测试失败先自己修复。

## 只有这些情况需要用户决策

- 需要取得用户独有且不可推断的商业许可、REST 私有协议或凭据；继续该项之前明确所缺的确切资料。与此同时继续其余所有不受影响的任务。
- 要做不可逆删除、对外发布、向他人发送数据、购买服务或修改用户没有授权的外部系统。
- 需求与证据发生不可调和冲突，且任何安全默认选择都会改变科学含义；先完成不依赖该选择的任务，再集中说明。

不把“安装路径不在默认位置”“两个代码实现选项”“某测试失败”“打包第一次失败”当作询问理由。先查实际环境、日志与官方文档，做可逆修复。

## 阶段完成记录格式

```text
阶段：v0.X.0
Git commit：
实现：任务 ID 与文件列表
验收命令/GUI 操作：
结果：PASS/FAIL/BLOCKED（每条证据路径）
数值变化：旧值、新值、条件、原因
未完成：明确依赖与下一动作
下一阶段：自动继续
```

不要把该阶段记录当作给用户的阶段性审批申请。它是本地开发证据，最后与产品一并交付。

## 最终交付标准

向用户报告的是最终产品：Windows one-folder ZIP、SHA-256、可复现项目/样例、真实后端能力表、科学回归、GUI/CLI/API 验收、逐模块 PASS/FAIL/BLOCKED、已知限制。不得说“全做完了”却没有可运行的 EXE、完整日志或检查命令。若外部 REST/许可证一项最终无法完成，报告其 BLOCKED，不牵连其它已完成模块，也不把该项写成 PASS。
