# GPU 加速规划评审（2026-11-10）

结论：GPU 是值得规划的可选后端；目前不能承诺端到端 5–50 倍、零 PCIe 开销、200–2000 原子可用或超越指定软件。应先验证当前 Direct SCF 正确性、完善 CPU 基线和内存模型，再以本机硬件开展小规模、可重复的 GPU 试验。

本轮只读当前源码、Git 状态和 nvidia-smi，联网查阅一手资料；未运行 GPU 数值测试、未安装任何工具、未修改内核。本机查询到 GeForce RTX 5060 Ti、8151 MiB，总显存；当时可用 6174 MiB、已用 1718 MiB，driver 591.86，compute capability 12.0。空闲显存是瞬时值。该结果不证明 CUDA Toolkit、编译器、依赖或运行环境可用。

当前源码已经出现 calchem-int/src/direct_fock.rs、DirectFockEngine、ScfOptions.direct，RHF/RKS/UHF/UKS 中也出现 Direct 选择及增量更新代码；这是代码存在性，不是本轮对正确性、最终刷新、线程内存或性能的验收。Git 工作区仍有大量用户修改。先按已有 Direct SCF 评审进行完整测试，不应沿用此前“尚无代码”的历史结论，也不应仅据新增文件宣布里程碑 1 完成。

## 对具体主张的判断

1. Vxc 网格点局部计算适合并行，但 AO 屏蔽、分块、稀疏聚合和矩阵写回/规约并非全然无依赖。混合泛函的精确交换、积分与对角化可能主导总时间；40–60% 和 20–100 倍均需同体系实测。Amdahl 公式：若原先 40% 时间无限加速，其余不变，总加速上限是 1/(1−0.4)=1.67。
2. RI-J 使用 (μν|P) 三中心积分与辅助基组度量矩阵，经过分解/求解与缩并；(ia|P) 属于特定轨道表示，不是一般 AO 定义。构建三中心积分、度量病态、内存/分块和误差也必须计入；它不自动解决混合泛函的精确交换 K。GPU GEMM 只是其中一环。
3. N=6224 的单张 float64 矩阵约 309.9 MB（十进制）；数十毫秒完成广义本征求解、及 5–20 倍都是未证实假设。测量必须包含 workspace、矩阵变换、同步、初始化和回传，并比较高性能多线程 CPU 而不是 Python 串行实现。
4. 24/80 GB 卡不能代表本机 8 GB。对 N=6224，两张自旋 Fock、密度、重叠、正交化、轨道系数、DIIS 历史、网格及库 workspace 需要同时计入；必须动态按空闲显存预算分块，分配失败安全报错。驻留 GPU 可减少重复传输，不意味着数据导入、初猜、结果输出和 host/device 同步零成本。
5. 不能把 FP32 前期、最后两步 FP64 当作可靠性保证。混合精度是可选实验：依据残差/误差估计自适应切换，最终用 FP64 严格重建物理 Fock、XC、能量并检查自洽残差；如密度变化须继续迭代。测试能量、梯度、偶极、自旋与阈值收敛，验证近简并和强消减情况。不要把未核实的具体 TeraChem/ORCA 实现机制当事实。
6. CUDA 是 NVIDIA 专用且需兼容驱动/运行时/工具链，feature gate 可确保 CPU 构建不强制依赖 GPU；Rust 宿主代码不等于完全无外部依赖。cuBLAS 与 Tensor Core 的可用数据类型/算法精度须分别明确，不能把任意 FP64 GEMM 当作 Tensor Core 吞吐。
7. wgpu 属于 Rust 跨平台 API，不是 Rust 语言官方 GPU 标准；依赖底层驱动与后端。WGSL 当前没有通用 f64 运行时类型，不能作为现阶段严谨双精度量化学主后端的等价替代。Vulkan 或 Metal 的其他接口有不同能力和限制，不能混为一谈。
8. GPU ERI 按壳角动量和收缩长度分桶有帮助，但不同负载、寄存器压力、筛选和规约仍需要测量；不能称其彻底消除 warp 发散。混合精度、原子加和顺序、可复现性和异常需单独处理。

## 建议顺序与验收门槛

- M0：冻结当前 CPU Direct 版本并备份；用独立 dense oracle 验证全量/增量、四种自旋方法、对称性、最终重建、错误预算和真实 RSS。建立小/中体系端到端 CPU 耗时分解；做设备、驱动、Toolkit、编译器和实际空闲显存只读盘点。先确认 D/E 缓存与输出位置。
- M1：只在可选 CUDA 后端做单算子原型（例如稠密对角化或分块 Vxc），先求正确性和数据搬运成本，再选择优先项。核心 API 返回明确错误，设备不可用时按显式策略回退并记录实际后端；不得静默改变方法。
- M2：CPU 端先有经验证的三中心积分、辅助基组、度量分解及 RI-J；再比较 GPU 缩并。FP64 直接法和 RI-J 的拟合误差分开衡量，不用系统性拟合误差掩盖 GPU 数值误差。
- M3：在上述基线稳固后，按壳类型分桶研究 GPU Direct J/K，先验证正确性和有界内存，之后逐步扩大系统；最终才探索混合精度、多 GPU 和真实 OPV 体系。
- LRC（范围分离 ERI）与 RI-J 的先后按论文应用需求决定，GPU 不是实现物理方法的前提；实现、模型身份及 CPU 参考先独立验证。

验收矩阵应锁定结构、基组与球/笛卡尔约定、泛函、网格、筛选阈值、SCF 误差、精度和 CPU/GPU 实际硬件。记录预热与冷启动、迭代次数、端到端时间、模块耗时、峰值 CPU RAM/VRAM、传输及 CPU/GPU 能量/梯度差。先 H2/H2O、开壳层、p/d 壳、弥散和近简并，再逐渐增大 AO；真实 Y6/p4D18 结构与 AO 数先核实。GPU 加速比不设先验保证。

## 一手来源

- GPU4PySCF 官方功能及限制：https://github.com/pyscf/gpu4pyscf/blob/master/README.md 。其现有方法/内存边界也不支持把 2000 原子视为自然可用；它仅作外部验证参考，不作为 CalChem 运行依赖。
- WGSL 规范：https://gpuweb.github.io/gpuweb/wgsl/ ；WebGPU 官方测试文档说明 f64 尚不是 WGSL 类型：https://gpuweb.github.io/cts/docs/tsdoc/classes/webgpu_util_conversion.F64Value.html 。
- NVIDIA CUDA Toolkit 发布说明：https://docs.nvidia.com/cuda/pdf/CUDA_Toolkit_Release_Notes.pdf 。实际需按本机驱动与目标 compute capability核实兼容性，不能仅凭 nvidia-smi 判断编译可用。

资料获取日期 2026-11-10；上游可能更新。原方案中不同型号显卡 FP64 规格、Gaussian 扩展支持及 ORCA/TeraChem 的具体混合精度策略尚未逐版本验证，不能作本轮已证实事实。
