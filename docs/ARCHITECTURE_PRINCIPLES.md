# CalChem 架构设计原则与工程开发铁律

> **版本**：1.0 (2026-11-05)  
> **生效范围**：CalChem 整个代码库（Rust 内核、PyO3 桥接层、Python 调度层、外部后端适配器）  
> **制定背景**：吸取传统量子化学软件（如 Gaussian、ORCA 的闭源与包袱）以及纯 Python/GUI 软件（性能低下、GIL 阻塞、内存指针崩溃、依赖地狱）的教训，确立 CalChem 长期健康演进的工程底座。

---

## 一、核心战略：两层语言法则（Two-Language Architecture）

CalChem 绝不走“纯 Python 科学计算”的歧路，也绝不走“无胶水纯底层难以扩展”的封闭老路，严格实行**职责物理隔离**：

```text
┌─────────────────────────────────────────────────────────────┐
│  第 2 层：Python 交互与调度层（Glue & Workflow API）         │
│  - 职责：高层 API、参数校验、任务队列、多引擎调度、结果持久化  │
│  - 原则：零密集数值循环、无状态纯胶水、异步安全                │
└──────────────────────────────┬──────────────────────────────┘
                               │ PyO3 C-ABI / NumPy 零拷贝
┌──────────────────────────────▼──────────────────────────────┐
│  第 1 层：Rust 高性能计算内核（Native Engine Crates）        │
│  - 职责：高斯积分、SCF 循环、张量/矩阵代数、解析梯度、几何优化 │
│  - 原则：内存安全、零垃圾回收、纯数学自洽、支持独立 CLI 编译     │
└─────────────────────────────────────────────────────────────┘
```

---

## 二、开发执行五大铁律

### 铁律 1：计算绝对下沉，Python 零密集算力（No Heavy Math in Python）
1. **禁止 Python 嵌套计算循环**：任何关于积分遍历、轨道系数缩并、网格采样、密度矩阵微调的双重及以上密集循环，必须在 Rust 内核（`crates/`）中实现。
2. **Python 仅作为数据搬运与高层 DSL**：Python 层的代码只负责构建计算请求对象（`CalculationRequest`）、检查输入合法性、将其丢入 Rust 内核，并在返回后进行结构化映射。
3. **严禁依赖纯 Python 慢速回退冒充正式能力**：若底层 Rust 尚未实现某个高级功能（如特定开壳层高阶相关能），必须显式标识为外部调度或实验性路径，不得用未经优化的纯 Python 脚本掩盖计算瓶颈。

### 铁律 2：Rust 核心解耦，支持原生独立运行（Decoupled Rust Core）
1. **脱离 Python 的自包含性**：`crates/` 下的 8 个核心模块（`model`, `basis`, `tensor`, `int`, `scf`, `grad`, `opt`, `prop`）不得引入任何 Python 依赖。
2. **支持独立 CLI 编译**：Rust 内核必须能够独立编译为本地自包含可执行程序（例如 `calchem-cli`），支持在没有 Python 环境的纯超算/容器节点上直接通过 JSON 文件读取并输出结果。
3. **PyO3 隔离在单独边界**：仅由 `crates/calchem-py` 单独负责 PyO3 与 numpy-rust 绑定，确保底层核心不受任何特定 Python 运行时的侵入。

### 铁律 3：平稳态自洽与严格强类型错误处理
1. **禁止假收敛与虚假输出**：SCF 未达到指定容差，必须返回 `CalcError::NotConverged`；几何优化线搜索受阻或未达三项判据，必须返回失败；绝不允许为了伪造全绿而返回假能量、假梯度或静默 pass。
2. **波函数平稳性铁律**：计算解析梯度前，波函数必须处于严格的数学平稳点（Stationary Point），即返回的 $(C, \epsilon, P, F)$ 必须严格满足 $F = F[P]$ 与对易子范数 $\|FPS - SPF\| < 10^{-8}$，杜绝因波函数未自洽导致的梯度数值漂移。
3. **强类型上抛**：Rust 底层错误通过 `Result<T, CalcError>` 向上冒泡，并在 PyO3 层精确映射为 `ScfNotConvergedError` 或 `RustCoreError`，绝不在底层吞异常。

### 铁律 4：数据与显示物理隔离，拒绝重量级 Python GUI 绑定
1. **内核纯无头（Headless）化**：CalChem 核心代码中绝对不包含任何 GUI 组件、视口句柄、绘图库调用。
2. **标准化数据契约**：空间轨道网格（Cube）、等值面、原子电荷、偶极矩均输出为标准格式（NumPy 内存缓冲区、标准 Cube 文件或 JSON 描述符）。
3. **前端解耦**：三维可视化与分子交互必须交由专业前端（如 WebGL、Three.js、Mol* 或极轻量桌面容器）处理，底层只提供极速、内存隔离的结构化计算服务。

### 铁律 5：工程防护与门禁全绿准则
1. **修改前强制备份**：在对算法核心或公共接口动工前，必须调用保护备份脚本记录原始文件的 SHA256 哈希。
2. **零容忍门禁**：一键门禁脚本 `tools/dev/check_all.ps1`（包含 Cargo Workspace 全绿、PyO3 编译、Pytest 全绿、Ruff 静态检查）必须无错误 exit 0。
3. **严禁篡改测试容差**：基准测试中的能量容差严格锁定在 $10^{-6} \sim 10^{-10}$ Eh，梯度误差上限锁定在 $10^{-4}$ Eh/Bohr，严禁通过调大公差或删除断言来伪造全绿。
