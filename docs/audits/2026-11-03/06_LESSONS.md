# 排错与经验记录

本文件记录本次检查中的工具问题和项目失败，避免下一次从同一个错误重新开始。本次没有严重误删、业务恢复或数据损失。

## 1. 大量文件列表输出被截断

起因：第一次把包含 2255 个归档文件的 Git 清单和多份源码同时输出，超过返回预算。修正：完整清单保存到 evidence/，当前运行代码与归档分开，关键文件按有界批次完整阅读。不要把截断输出当作读完，也不要不断重复整仓库扫描。

## 2. Windows 下 rg 的通配符参数

现象：把 `crates\calchem-basis\data\*.json` 直接作为文件参数传给 rg，出现 os error 123。原因：PowerShell 没有按预期替原生程序展开该通配符。正确方式是 `rg <pattern> crates/calchem-basis/data -g '*.json'`，或者用 Get-ChildItem 明确枚举再读取。本次随后读取两个明确 JSON 并验证元素列表，没有遗漏该检查。

## 3. 写入保护拦截 pytest 空设备

现象：首轮 pytest INTERNALERROR，审计 hook 拒绝 `\\.\nul`。这是验证工具的防护规则把空设备当成审计目录外写入，不是项目单元测试失败，也不是 C 盘文件已经写入。

修正：为 pytest 显式指定审计 E 盘日志文件，保持保护规则。保留初次日志，重跑后得到真实 19 passed / 9 failed。不要简单关闭所有保护或把 INTERNALERROR 混入业务失败统计。

## 4. Rust 全量测试编译失败后如何继续

现象：一个集成测试格式字符串错误导致整个 workspace 测试中断。处理：保留完整失败日志，运行独立 library、basis/SCF 和其它可编译积分测试，明确列出没有执行到的测试。不能因库编译成功就声称全部测试通过，也不能修改用户源码后再把结果描述成原状态。

## 5. 参考数字也需要验证

现象：Boys 和 H₂ 动能测试失败。处理：先计算定义积分和独立闭式结果，而不是直接改算法或放宽阈值。结果显示多处固定参考不准确，动能独立公式与 Rust 完全一致。后续参考数据需附生成方法、几何、单位、基组、理论级别和精度，不只保存一个小数。

## 6. 历史 PASS、文件名和版本号都不是当前证据

- 旧验收说 ORCA 已通过，但当前结果构造路径能复现 NameError。
- 旧记录说频率可用，当前统一 Native 能力表却没有 frequency，工具文件存在不等于入口连通。
- test_core_rust.py 文档写有梯度/优化/零拷贝测试，但实际扩展没有这些接口。
- capability 列出某方法不代表构造签名一致；本次构造阶段就发现多处断点。
- 默认服务的“环境变量优先”描述不代表实际表达式优先顺序，必须查看并实测。
- 单次诊断脚本退出零只表示收集完成；应读取 pytest/cargo 各自的真实退出码和断言结果。

## 7. 后续重大修复的记录模板

每次记录：触发输入与错误 → 影响范围 → 最小复现 → 原因 → 修改文件及备份 manifest → 修复方法 → 数值/功能验证 → 未验证范围 → 回滚命令。优先补充本轮已有证据，不覆盖旧事故记录。
