# CalChem 同精度性能优化执行方案

目标是在固定计算精度与可比资源下，让 PTQ10 B3LYP/STO-3G、BTP-4F PBE/STO-3G 的端到端时间逐步低于 Gaussian 16。每个目标先标为工程目标，是否达到以同机复测的中位数为准。采用现有 Rust 核心和张量库实现，参考 REST 的 RI-JK、格点批处理和矩阵收缩思路。每项改动先做定点验证，再合并到实际 CLI 与 Python 路径。

## 第 0 阶段：建立可复现基线

1. 冻结当前 CLI、Python 扩展和待改源码的 SHA256，备份到 E 盘。建立独立运行目录，保留输入、环境、退出码、GPU 核次数、每步日志、峰值内存和版本。
2. 分别建立 CPU 4 线程对 CPU 4 线程，以及 GPU 开启的端到端比较。明确 `%mem=2GB` 与进程工作集的定义不同，逐项记录各程序可用内存及 GPU 显存。
3. 对两体系同一几何、电子态、方法、基组，先核算功能定义、格点收敛与 RI 误差。Gaussian 和 CalChem 的 Coarse 名称不能证明网格相同。对较小分子和可计算的片段，用同一密度与同一格点比较 CalChem 精确 J、RI-J；对完整分子用多个网格层次和可承受的 J 对照确认误差。记录总能量和研究所需相对能量，不能只用两个巨大体系的绝对能量差判断方法错误。
4. 每个配置预热后串行计时至少 3 次，记录每次结果与中位数。对每一步记录 ΔE、密度 RMS / 最大变化、交换子范数及最终残差，以共同误差目标约束停止条件。各代码计时口径、CPU 型号、线程和 GPU 型号留档。

产物是能量误差表、CPU 与 GPU 两套基准脚本、原始日志。当前单次记录仅用作起点。若两程序无法使用相同节点或相同辅助基，则明确为精度收敛比较，给出误差并避免标记为完全同算法。

## 第 1 阶段：降低 SCF 重复迭代

目标是减少 26 / 53 步带来的重复 Fock 和 Vxc 调用，先做同代码 A/B，再决定默认策略。

- 在 `crates/calchem-scf/src/rks.rs` 的 0.3 固定阻尼入口，加入仅用于实验的可配置策略。对比现状、较早退出阻尼和基于残差趋势的自适应阻尼。DIIS 条件数差或振荡时回退到稳定策略。沿用现有选项与磁盘 DIIS 错误传播。
- 同时对比现有初猜与可用的原子密度初猜，并比较 DIIS 向量长度和开始迭代步数。先运行小体系、PTQ10 和 BTP-4F，再覆盖带电、开壳层及难收敛体系。仅在受影响的 RKS 路径实际有效后再考虑向其他求解器复用。
- 对每一候选记录每步密度、能量、交换子，重建最终物理 Fock。保留密度阈值、交换子及固定点复核。候选失败时使用现有稳定路径或明确报不收敛。

通过条件是固定密度或最终收敛结果与原方法吻合，满足相同最终残差，已有难收敛测试无回归。初步目标是两个大体系的迭代步数相对本轮各下降至少 20%，这是实验目标，未达到时保留诊断并继续其他阶段。

## 第 2 阶段：加速 BTP-4F 的 RI-J 初始化

当前初始化 51.82 秒，需先在 `crates/calchem-int/src/density_fitting.rs` 的辅助基生成、二中心度量、`SpdFactor::for_solve`、显著壳对、三中心张量生成以及首次 GPU 上传分别加计时和内存计数。

按实测最大的子阶段优化。三中心生成如为热点，预计算一次基础壳对与原始高斯对，按辅助壳和显著 AO 壳对分批，重复利用工作区并避免每个块分配。度量因子如为热点，减少不必要的矩阵复制，保留平移 Cholesky 满秩判定与近线性相关的谱截断。GPU 若受传输影响，保持只读张量常驻并单独计时上传与核执行。所有缓存计入现有内存预算并保留超预算回退。

通过条件是固定密度下 CPU 稠密、压缩、流式和 GPU J 矩阵及能量一致，覆盖非对称密度、近线性相关、预算不足和解析梯度。初步目标是初始化中位时间从约 52 秒降到 30 秒以内。只有定位到实际热点后确定具体改法。

## 第 3 阶段：加速 BTP-4F 的 RKS 数值格点

当前主 SCF Vxc 55.72 秒。在 `crates/calchem-dft/src/vxc.rs`、`ao_grid.rs` 中把已有逐点 AO 值和梯度按有限批次组织，利用活跃 AO/壳对做密度与 Vxc 的块矩阵运算，使用仓库现有 faer 或自有矩阵核。每批先筛活跃壳，限制临时矩阵大小。比较重算 AO 与缓存批数据的时间、内存，保留 streaming 网格路径。

先在固定网格和固定密度比较 XC 能、Vxc 每个元素、对称性。再检查 B3LYP、PBE、PBE0、范围分离泛函，以及网格运动对应的解析梯度和有限差分。缓存失效要覆盖几何与基组变化。保留线程数控制，防止 Rayon 与矩阵库嵌套超额并行。

通过条件是固定密度的 XC 能量差不超过 1e-9 Eh、Vxc 最大元素差不超过 1e-9 Eh，梯度满足现有有限差分测试精度。初步目标是 BTP-4F 主 SCF Vxc 中位时间从约 56 秒降到 30 秒以内。对不同计算路径记录点数、筛选阈值和误差。

## 第 4 阶段：加速 PTQ10 精确交换 K

当前主 SCF 双电子 26.05 秒。对 `crates/calchem-int/src/direct_fock.rs` 与 `eri.rs` 增加缓存命中、计算 quartet 数、屏蔽数和实际 CPU 时间统计。对缓存不命中热区，按壳对类型批处理，复用原始高斯对和工作区，改进连续内存布局与向量化，避免逐 quartet 重复分配。按基组、内存限制和实测命中率调整有界缓存策略。

若 CPU 版本仍无法达到目标，实施分批 FP64 GPU 四中心积分原型，先支持 PTQ10 使用的角动量，其他情况逐批走 CPU 计算。原型通过固定密度 K、不同阈值、对称性、不同 ω、GPU 不可用及 CPU 回退验证，再接入正常入口。RI-K 可作为另一条有独立辅助基和精度开关的路径，需要从固定 K、能量差、梯度及真实 OPV 相对能量完整评估。

初步目标是 PTQ10 主 SCF 双电子从约 26 秒降到 10 秒以内。该目标可能需要新的近似或 GPU 算法，以实测与误差约束决定。

## 第 5 阶段：集成验收

1. 在所有优化稳定后，重编译 CLI 与 Python 扩展，核对扩展 SHA256。完整执行 `scripts/cargo_test.ps1` 和 `scripts/run_pytest.ps1 tests/unit`，检查退出码与跳过项，并执行真实 OPV 验证。
2. 重新运行 4 线程 CPU 及对应 GPU 基准，各至少 3 次。验证相同坐标、电子态、能量和密度误差，逐个输出中位时间、内存、SCF 步数、各阶段时间、GPU 核调用和回退。
3. 以本机同设置 Gaussian 4 线程的重新运行结果为正式比较。阶段性目标是 PTQ10 低于 16.81 秒、BTP-4F 低于 107.10 秒。旧数字用于方向判断，正式结论以重跑和精度对齐结果为准。
4. 交付性能与精度结果、每个阶段的影响及未达标项、原始日志、变更文件和 E 盘备份 SHA256。恢复操作在独立候选目录进行。

## 执行节奏

先完成基准采集与 SCF A/B，再优化 BTP-4F 初始化和格点，随后处理 PTQ10 的 K，最后全量回归。每个阶段完成后即运行定点测试和基准，保留有效改动，失败实验保留日志。阶段目标用于决定是否继续优化，不以放宽精度换取通过。项目根目录已有大量工作，修改具体文件前备份对应原件。
