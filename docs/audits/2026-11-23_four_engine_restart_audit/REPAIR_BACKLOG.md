# CalChem 缺陷清单与根治计划

基于 11 月 23 日四引擎现场审计、当前 v0.2.2 源码（HEAD `9f57bd7`）和此前的有效实测。本清单覆盖已发现的未闭合问题。P0 影响计算模型、结果正确性或任务是否真实完成，P1 影响精度、可靠性或主要性能目标，P2 为能力扩展及规模验收。标注“待归因”的条目先做可证伪对照。

## 先废止现有速度排名

咖啡因表是执行记录，只有启动、完成、耗时窗口和各自结果可用于追踪。CalChem 用 16 个 Rayon 线程，Gaussian 和 REST 配置 8 线程，ORCA 用 8 个 MPI 进程。同一输入坐标下，四者还存在 260 / 246 / 216 AO、Coulomb/交换近似、网格与收敛判据差异。因此 29.06 s、31.5 s、35.84 s、29.31 s 无法用于公平排名。Gaussian Opt+Freq 需分开读两段 Link1，163.8 + 273.4 = 437.2 s。旧 C1 的 STO-3G 结果仅作为该配置下的运行记录。

新基准的计算清单由脚本生成，预检输入、解析实际启动输出并校验。CPU 主表固定同机、同一组 8 个物理核心的 CPU 资源、同一时间一个计算、可比内存限制、统一的进程墙钟计时。记录 MPI rank、每 rank BLAS/OpenMP 线程、Rayon 线程、WSL 可用资源和实际 CPU 亲和性。进程树超配、隐含 GPU、模型不匹配、指标未确认或物理产物缺失的结果不得进入排名。内部阶段计时保留用于分析热点。

同一比较组锁定几何、原子顺序、电子态、任务、泛函变体、轨道基组/5D-6D、色散、溶剂、J/K 近似和精度目标。分别验证四中心参考及各快速近似的误差。同一 CPU/GPU 对照只切换硬件路径，保留实际核调用和回退。积分节点无法统一时，逐引擎跑网格收敛序列，按共同的可验证误差预算比较，并标明实际格点不同。阈值数值相同不能代替最终残差、梯度等结果检查。首轮全四方可用无 d 极化的 6-31G 做流程校验，带极化的验收按 5D 和 6D 分别建立 Gaussian 参考。

## 已确认的产品与工程缺陷
