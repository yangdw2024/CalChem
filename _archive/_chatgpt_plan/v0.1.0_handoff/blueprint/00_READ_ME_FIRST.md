# CalChem 完整产品蓝图包：本地 Agent 执行入口

本文件是执行入口。先读完本目录所有蓝图文件，再阅读 `handoff/00_MASTER_CONTEXT.md`、`handoff/06_STRATEGY.md`、`handoff/03_NUMERICAL_BASELINE.md` 和 `handoff/05_ENV_AND_CONSTRAINTS.md`，再执行本仓库任务。

## 给 Agent 的强制执行规则

1. 用户要的是最终产品质量。不要在阶段边界停下来问用户“是否继续”，也不要因为存在多个合理实现方式而停下；按照本蓝图已作出的默认决策继续。
2. 先检查仓库、环境和已有实现，再做最小可逆改动。保留原始数值基线；任何改动不得悄悄覆盖参考数据。
3. 所有本地代码、配置、文档、测试、界面、构建和打包工作都要持续推进，直到本蓝图最终验收表中的每项都通过，或被明确标成外部阻塞并提供可复现证据。
4. 不准把 TODO、占位实现、mock、录屏或 fixture 说成真正可用的后端。每个功能必须标注“已实现并验收”“已实现但未验收”或“未实现”。
5. 不得并行运行多个 heavy 量化计算；UI 可以响应，任务队列必须串行执行。不要让测试框架、批处理脚本或 agent 并行启动 Gaussian/ORCA/native heavy jobs。
6. Windows 环境优先使用 PowerShell 7 友好命令；Python 环境、依赖、构建产物、计算缓存与用户项目放到非 C 盘路径。默认根目录为 `D:\CalChem`，用户数据根目录为 `D:\CalChemData`，都可配置。
7. 在完整验收前不向用户提问或汇报中间结果。仅当继续执行会触及不可逆删除、外发数据、未授权付费/许可、凭据或外部发布时才停止依赖该动作；其余独立任务继续完成。遇到缺少 Gaussian/ORCA 等可执行程序时，继续完成所有不依赖它的工作，保留清楚的阻塞证据，不用模拟结果冒充验收。
8. 每个阶段结束后自行运行该阶段验收，再继续下一阶段。失败先定位、修复、重跑；不能把“命令已启动”当作通过。
9. 最终仅在产品最终验收结束后向用户交付：安装包/便携包、版本号、验收矩阵、每个后端的实测状态、已知限制、复现命令和阻塞项。
